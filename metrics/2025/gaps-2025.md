# Cross-vendor metric alignment gaps — 2025

Comparability assessment of AWS, Google Cloud, Microsoft Azure and Oracle Cloud sustainability metrics
for 2025, against the Cloud Region Metadata schema. Built from the per-vendor metrics docs in this
folder. The goal is to show where the providers' metrics are **not comparable** and what each should
change so a customer can compare regions across clouds like-for-like.

## At-a-glance

| Metric | AWS | Google | Azure | Oracle |
|---|---|---|---|---|
| PUE | ✅ per-region, CY (regional avg for newer regions) | ✅ per-datacenter, CY | ⚠️ macro-region only, FY | ✅ per-region, but CY2023 & 12-mo rolling |
| WUE (L/kWh) | ✅ per-region, CY | ❌ not published (gallons only) | ⚠️ macro-region only, FY | ❌ not in this data sheet |
| Water withdrawn (litres) | ✅ per-region/country, CY | ⚠️ by location, gallons | ⚠️ global only | ❌ |
| Carbon-free energy, per-region location-based | ❌ | ✅ hourly (but 2025 pending) | ❌ | ❌ |
| Renewable/CFE, market claim | ✅ per-grid list | ✅ global 100% | ✅ global 100% | ✅ per-region RE% |
| Grid carbon intensity, own data | ❌ (3rd-party) | ✅ (Electricity Maps, 2025 pending) | ❌ | ❌ (3rd-party) |
| Reporting period | calendar Jan–Dec | calendar Jan–Dec | **fiscal Jul–Jun** | **fiscal Jun–May** (+ CY2023 PUE) |

## Metric-by-metric

### Power Usage Effectiveness (PUE)
| Vendor | Reports? | Granularity | Period | Boundary |
|---|---|---|---|---|
| AWS | yes | per-region (regional avg for newer/smaller regions — Milan, Zurich, Seoul, Malaysia, NZ) | CY Jan–Dec | operated DCs |
| Google | yes | per-datacenter (→region) | CY, annual | entire owned+operated fleet |
| Azure | partial | macro-region (Americas/APAC/EMEA) | FY Jul–Jun | owned+operated |
| Oracle | yes | per-region | **CY2023** (stale), 12-mo rolling, ~88% of sites | revenue regions |

**Gaps → asks:** Azure should restore **per-region, calendar-year** PUE (it stopped after 2022). Oracle
should publish **current-year** per-region PUE (its per-region PUE is still CY2023) and state full-site
coverage rather than ~88%. AWS should give an individual PUE for its newer regions rather than a regional
average. All four should converge on a single boundary definition (operated vs owned) and a calendar-year window.

Transparency note: AWS's fact sheets also disclose **ISO 50001 / ISO 14001 certification and EU Code of
Conduct on Data Centre Energy Efficiency conformance** per (EU) region — a useful energy-governance signal
the other providers should publish per region too.

### Water Usage Effectiveness (WUE) and water withdrawal
Only **AWS** publishes per-region WUE in L/kWh (and even then several regions show `--`). **Azure** gives
only macro-regional WUE; **Google** reports water in **million gallons by location**, not L/kWh; **Oracle**'s
FY2025 data sheet omits WUE. Separately, AWS's fact sheets now give a **per-region annual water withdrawal
in litres** — a strong match for the schema's `total-water-input` column (Google gives comparable
withdrawal but by location in gallons; Azure only globally). **Gaps → asks:** Google and Oracle should
publish WUE in L/kWh per region; Azure should return to per-region granularity; all should report annual
per-region water withdrawal in a common unit (litres) so `total-water-input` can be populated consistently.

### Carbon-free / renewable energy — the central gap
Two fundamentally different things are all labelled "carbon-free"/"renewable":
- **Location-based, per-region, hourly** — physically meaningful (what's actually on the local grid,
  matched hour by hour). **Only Google publishes this** (`provider-cfe-hourly`), and its **2025 values
  are not yet released** in the machine-readable dataset.
- **Market-based, annual, matched** — AWS, Azure and Oracle each claim ~100% renewable by netting
  purchases (RECs/PPAs), in several cases **across electrically-unconnected grids**. This is *not* useful
  as a per-region physical figure. AWS is a partial exception: it names a per-grid list of regions matched
  *within* the grid (kept as per-region `market = 0`). Oracle's RE% at least **varies per region** (0–100%),
  so it carries some per-region signal, but it's still a market-based match.

**Gaps → asks:** AWS, Azure and Oracle should publish a **per-region, location-based, ideally hourly**
carbon-free-energy percentage like Google, rather than (or in addition to) a global market-matched claim.
Google should publish the current year's per-region CFE on the same cadence as its report.

### Grid carbon intensity
Only Google publishes a per-region grid carbon intensity (via Electricity Maps; 2025 pending). AWS, Azure
and Oracle rely on the project sourcing third-party (Electricity Maps / WattTime) data. **Gap → ask:**
providers should either publish the per-region location-based grid intensity they use, or converge on a
common third-party source and vintage so the numbers are consistent.

### Reporting period & boundary — the most-overlooked gap
AWS and Google report **calendar year (Jan 1 – Dec 31)**. **Azure (FY Jul 1 – Jun 30)** and **Oracle
(FY Jun 1 – May 31)** report **fiscal years that end in the middle of the calendar year** — so an
Azure/Oracle "2025" figure covers roughly H2-2024 + H1-2025 and ends ~mid-2025. It is **not** the same
window as an AWS/Google "2025" figure. Oracle compounds this by mixing a fiscal-year RE% with a
calendar-year (CY2023) PUE in the same region row. The merged table aligns these fiscal→calendar only
**nominally**. **Gap → ask:** fiscal-reporting vendors should additionally disclose calendar-year figures
(or state the exact period per metric) so same-year cross-cloud comparisons are like-for-like.

### Metrics published by some vendors with no common schema home
Oracle `tCO₂e/$USD` (emissions per revenue); Microsoft GHG-by-region and total-energy tables; AWS
embodied carbon and water-restoration volumes; Google Compute Carbon Intensity (gCO₂e/FLOP) and TPU
lifecycle emissions. **Consider** whether the schema should grow to capture emissions-per-revenue or
per-region GHG, or whether these stay out of scope.

## Summary of recommendations per vendor
- **AWS:** publish per-region location-based (ideally hourly) CFE and per-region grid carbon intensity, so it's not market-only; keep the calendar-year, per-region PUE/WUE it already does well.
- **Google:** publish the current year's per-region hourly CFE + grid carbon on the report cadence (don't lag a year); add per-region WUE in L/kWh.
- **Azure:** restore **per-region** PUE/WUE (lost since 2022) and provide **calendar-year** figures alongside fiscal; publish per-region location-based CFE.
- **Oracle:** publish **current-year** per-region PUE (not CY2023) and per-region WUE; provide calendar-year alongside fiscal; keep the useful per-region RE% but clarify it's market-based.

## Year-over-year
First full cross-vendor gaps report in this format. Baseline for tracking comparability improvements in
future years. Notable 2025 movement: Oracle RE% regressed in several regions (Frankfurt, Serbia, S.
Korea North) while improving in others (Osaka, Melbourne); Azure and Google fleet PUE essentially flat
(1.17 FY / 1.09 CY respectively); AWS global WUE continued to fall (0.15 → 0.12).
